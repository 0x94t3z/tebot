IMPLEMENTASI DAN PENGUJIAN

4.1 Implementasi Sistem

Sistem yang dibuat pada penelitian ini berbentuk chatbot Telegram untuk layanan FAQ SAMSAT Bandung Timur. Chatbot dipakai sebagai media tanya jawab antara pengguna dan sistem. Pengguna bisa memilih kategori melalui tombol menu atau langsung mengetik pertanyaan dalam bentuk teks.

Backend chatbot dijalankan menggunakan Cloudflare Workers. Telegram mengirim pesan pengguna ke Worker melalui webhook. Setelah request masuk, Worker membaca jenis input yang dikirim pengguna. Input tersebut bisa berupa command, pilihan tombol, pertanyaan bebas, voting kepuasan, atau input yang tidak didukung seperti foto dan voice note.

Bot ini tidak memakai AI generatif. Jawaban yang dikirim berasal dari dataset FAQ yang sudah disiapkan. Pencocokan antara pertanyaan pengguna dan dataset dilakukan dengan metode pattern matching berbasis aturan. Regex dipakai sebagai teknik pendukung untuk normalisasi istilah dan pendeteksian pola pertanyaan tertentu.

4.1.1 Lingkungan Implementasi

Lingkungan implementasi sistem terdiri dari Telegram Bot API, Cloudflare Workers, TypeScript, Cloudflare KV, dan Vitest. Telegram Bot API dipakai untuk menerima dan mengirim pesan. Cloudflare Workers menjalankan logika backend. TypeScript dipakai untuk menulis program. Cloudflare KV menyimpan data yang berubah, misalnya profil responden, voting kepuasan, dan daftar message ID untuk command /clear. Vitest dipakai untuk pengujian otomatis.

4.1.2 Alur Kerja Sistem

Alur sistem dimulai dari pesan yang dikirim pengguna di Telegram. Telegram meneruskan pesan tersebut ke endpoint webhook yang sudah didaftarkan pada server Telegram. Cloudflare Workers menerima request tersebut dan memvalidasi secret webhook. Jika request valid, sistem melanjutkan proses sesuai jenis input.

Jika input berupa command /start, bot menyimpan data dasar pengguna dan menampilkan menu utama. Jika input berasal dari tombol kategori, bot menampilkan daftar pertanyaan pada kategori tersebut. Jika input berupa pertanyaan bebas, sistem menjalankan proses pattern matching terhadap dataset FAQ. Jika input berada di luar konteks SAMSAT, bot mengirim fallback.

User Telegram
  -> Telegram Bot API
  -> Webhook Cloudflare Workers
  -> Validasi secret webhook
  -> Routing input
  -> Pattern matching atau fallback
  -> Balasan Telegram
  -> Penyimpanan data riset dan voting

4.2 Implementasi Dataset FAQ

Dataset FAQ menjadi sumber jawaban utama pada chatbot. Dataset aktif berisi 150 data FAQ yang disimpan dalam file src/data/faq-samsat-bandung-timur.json. Data disimpan dalam format JSON agar pertanyaan dan jawaban tidak bercampur dengan kode algoritma. Pemisahan ini membuat perubahan dataset lebih mudah dilakukan ketika ada jawaban yang perlu diperbaiki atau pola pertanyaan baru yang perlu ditambahkan.

Setiap data FAQ memiliki lima field, yaitu id, category, question, answer, dan source. Field id dipakai sebagai identitas data. Field category dipakai untuk mengelompokkan FAQ ke dalam menu. Field question berisi pertanyaan utama. Field answer berisi jawaban yang dikirim bot. Field source berisi sumber rujukan jawaban.

4.3 Implementasi Metode Pattern Matching

Metode pattern matching diterapkan untuk mencocokkan pertanyaan pengguna dengan dataset FAQ. Sistem tidak membuat jawaban baru. Sistem hanya memilih jawaban yang sudah tersedia pada dataset. Karena itu, kualitas jawaban sangat bergantung pada kualitas dataset dan pola pencocokan yang dibuat.

Proses pencocokan dimulai dari normalisasi input. Teks pengguna diubah menjadi huruf kecil, tanda baca dibersihkan, variasi istilah disamakan, lalu teks dipecah menjadi token. Setelah itu sistem menghapus stop word, memperluas beberapa sinonim sederhana, dan membandingkan token input dengan pertanyaan FAQ, kategori, custom pattern, dan regex pendukung.

Input pengguna
  -> normalisasi teks
  -> segmentasi multi-intent
  -> tokenisasi
  -> penghapusan stop word
  -> perluasan sinonim
  -> pencocokan pattern
  -> scoring kandidat FAQ
  -> jawaban terbaik atau fallback

Gambar 4.2 Alur pattern matching

4.3.1 Normalisasi Teks

Normalisasi teks dipakai agar variasi penulisan pengguna menjadi lebih seragam. Contohnya, kata drivethru, drive-thru, dan drive through disamakan menjadi drive thru. Istilah nopol, no polisi, dan nomor polisi juga disamakan. Dengan cara ini, sistem tidak perlu membuat data FAQ baru hanya karena pengguna menulis istilah dengan bentuk berbeda.

Normalisasi juga menangani beberapa kata tidak baku yang sering muncul pada chat, seperti ilang menjadi hilang, belom menjadi belum, dan ngurus menjadi cara. Aturan seperti ini membuat input informal tetap punya peluang cocok dengan dataset.

4.3.2 Tokenisasi, Stop Word, dan Sinonim

Setelah dinormalisasi, input dipecah menjadi token. Token yang terlalu umum dibuang agar pencocokan fokus pada kata yang membawa makna. Kata seperti apa, bagaimana, kalau, saya, dan min tidak cukup kuat untuk menentukan jawaban, sehingga tidak dijadikan dasar utama pencocokan.

Sistem juga memakai kelompok sinonim sederhana. Misalnya, alamat, lokasi, tempat, dan dimana dianggap saling dekat. Kelompok bayar, pembayaran, dan dibayar juga dianggap dekat. Sinonim ini tidak membuat bot memahami bahasa bebas seperti LLM, tetapi cukup membantu untuk variasi pertanyaan yang masih berada dalam domain SAMSAT.

4.3.3 Custom Pattern

Custom pattern dipakai untuk mengarahkan variasi pertanyaan ke FAQ tertentu. Misalnya FAQ tentang STNK hilang tidak hanya cocok dengan pertanyaan utama pada dataset, tetapi juga dengan variasi seperti stnk saya hilang, stnk ilang harus ngapain, atau kalau stnk hilang bagaimana.

Custom pattern berguna saat jawaban sudah ada, tetapi cara pengguna bertanya berbeda dari pertanyaan utama. Dengan custom pattern, dataset tidak perlu diisi banyak baris duplikat untuk jawaban yang sama.

4.3.4 Regex Pendukung

Regex dipakai sebagai pendukung pattern matching. Regex membantu sistem mengenali pola frasa yang punya banyak bentuk. Contohnya pola STNK hilang, pajak lima tahunan, TNKB rusak, pembayaran SIGNAL belum berubah, dan cek fisik untuk mutasi.

Regex tidak menggantikan pattern matching. Keputusan akhir tetap memakai scoring. Regex hanya memberi sinyal tambahan bahwa input pengguna memiliki pola yang kuat terhadap FAQ tertentu.

4.3.5 Scoring dan Pemilihan Jawaban

Setiap FAQ diberi skor berdasarkan kecocokan dengan input pengguna. Komponen skor berasal dari kecocokan frasa, custom pattern, regex, overlap token, cakupan token, dan token domain. Kandidat FAQ dengan skor tertinggi dipilih jika nilainya melewati batas minimum. Jika tidak ada kandidat yang cukup kuat, bot mengirim fallback.

Skor ini disebut skor relevansi internal. Skor tersebut bukan akurasi machine learning karena sistem tidak melakukan proses training model statistik. Skor dipakai untuk memilih jawaban yang paling dekat dengan input pengguna.

4.3.6 Multi-Intent dan Fallback

Sistem juga menangani input yang berisi lebih dari satu pertanyaan. Misalnya pengguna menulis, STNK saya hilang dan pajak motor mati bertahun-tahun gimana?. Sistem memecah pertanyaan tersebut menjadi beberapa segmen, lalu menjalankan pattern matching pada setiap segmen yang bermakna.

Fallback dipakai ketika pertanyaan tidak berada dalam domain SAMSAT atau tidak cukup cocok dengan dataset. Contohnya pertanyaan tentang paspor, ATM, listrik, SIM, atau gym tidak dijawab dengan FAQ SAMSAT. Bot mengirim pesan bahwa pertanyaan belum tersedia atau berada di luar topik layanan.

4.4 Implementasi Tampilan Chatbot

Tampilan chatbot dibuat langsung di Telegram. Setelah pengguna menjalankan command /start, bot menampilkan pesan pembuka dan menu kategori. Pengguna bisa memilih kategori, membuka daftar pertanyaan, menekan pertanyaan tertentu, atau mengetik pertanyaan bebas.

Jawaban FAQ menampilkan pertanyaan yang dipilih sistem, isi jawaban, dan sumber rujukan. Setelah jawaban dikirim, bot menampilkan tombol voting Memuaskan dan Tidak Memuaskan. Menu utama juga ditampilkan kembali agar pengguna bisa melanjutkan pencarian tanpa mengetik /start lagi.

4.5 Implementasi Penyimpanan Data Riset

Data riset disimpan menggunakan Cloudflare KV. Data yang disimpan terdiri dari profil dasar pengguna Telegram dan data voting kepuasan. Profil dasar disimpan setelah pengguna menjalankan /start. Data yang dicatat meliputi Telegram ID, username, nama depan, nama belakang, kode bahasa, waktu mulai, dan waktu terakhir aktif.

Voting kepuasan disimpan per FAQ. Satu pengguna hanya memiliki satu vote aktif untuk satu FAQ. Jika pengguna mengganti pilihan, sistem memperbarui pilihan lama, bukan menambah suara baru. Cara ini mencegah satu pengguna memberi suara ganda pada FAQ yang sama.

Data Keterangan

Voting kepuasan Pilihan Memuaskan atau Tidak Memuaskan pada setiap FAQ.

4.6 Pengujian Sistem

Pengujian sistem dilakukan lewat dua jalur. Jalur pertama adalah pengujian otomatis menggunakan Vitest. Jalur kedua adalah uji coba langsung melalui Telegram bot. Pengujian otomatis memeriksa fungsi program, sedangkan uji coba Telegram memeriksa pengalaman pengguna pada media implementasi yang sebenarnya.

4.6.1 Black Box Testing

Pengujian black box dilakukan dengan memberi input kepada chatbot dan membandingkan output dengan hasil yang diharapkan. Penguji tidak perlu melihat detail scoring di dalam fungsi matcher. Yang diperiksa adalah apakah input tertentu menghasilkan FAQ yang benar atau fallback.

No Skenario Input Output yang Diharapkan

2 Urutan kata berubah Kalau STNK hilang bagaimana? FAQ STNK hilang.
3 Pertanyaan natural Plat motor saya rusak karena kecelakaan. FAQ TNKB rusak.
4 Dua intent dalam satu pesan Syarat balik nama dan mutasi apa saja? Jawaban balik nama dan mutasi.
5 Di luar konteks Bisa perpanjang paspor di Samsat? Fallback.

4.8 Analisis Hasil

Berdasarkan hasil pengujian, sistem mampu mencocokkan pertanyaan pengguna dengan FAQ yang relevan jika input masih memiliki kata kunci, pola frasa, atau konteks yang sudah diwakili dalam dataset. Pertanyaan seperti Kalau STNK hilang bagaimana? tetap dikenali karena pola STNK hilang sudah diwakili oleh custom pattern dan regex pendukung.

Regex membantu sistem pada istilah yang memiliki banyak variasi penulisan. Contohnya, 5 tahunan, lima tahun, dan ganti plat dapat diarahkan ke konteks pajak lima tahunan. Custom pattern membantu pertanyaan yang lebih natural, misalnya pertanyaan tentang pemilik kendaraan yang sudah meninggal atau kendaraan luar daerah yang ingin dimutasi ke Bandung.

Fallback juga bekerja sebagai pembatas domain. Saat pengguna bertanya tentang paspor, ATM, listrik, SIM, atau perbaikan motor, bot tidak memaksakan jawaban dari dataset SAMSAT. Ini penting karena pattern matching berbasis aturan bisa salah memilih jawaban jika tidak diberi pembatas konteks.

Keterbatasan sistem tetap ada. Bot tidak memahami semua variasi bahasa seperti AI generatif. Jika pengguna menulis pertanyaan dengan pola yang belum pernah diwakili oleh dataset, custom pattern, atau regex, bot bisa mengirim fallback. Kondisi tersebut menjadi dasar untuk memperbarui dataset dan menambah regression test pada pengembangan berikutnya.

BAB V
KESIMPULAN DAN SARAN

5.1 Kesimpulan

Berdasarkan implementasi dan pengujian yang telah dilakukan, beberapa kesimpulan yang diperoleh adalah sebagai berikut.

  1. Chatbot FAQ SAMSAT Bandung Timur berhasil dibuat dalam bentuk bot Telegram dengan backend Cloudflare Workers. Bot menerima pesan melalui webhook dan mengirim balasan menggunakan Telegram Bot API.
  2. Metode pattern matching berhasil diterapkan untuk mencocokkan pertanyaan pengguna dengan dataset FAQ. Proses pencocokan dilakukan melalui normalisasi teks, tokenisasi, penghapusan stop word, perluasan sinonim sederhana, custom pattern, regex pendukung, dan scoring.
  3. Dataset FAQ berjumlah 150 data dan disimpan dalam format JSON. Dataset tersebut memuat kategori, pertanyaan, jawaban, dan sumber rujukan.
  4. Regex berperan sebagai teknik pendukung. Regex dipakai untuk menyamakan variasi penulisan dan mengenali pola frasa tertentu, sedangkan pemilihan jawaban akhir tetap memakai scoring pattern matching.
  5. Sistem dapat menangani pertanyaan bebas, pilihan menu, dan pesan multi-intent selama input masih berada dalam cakupan dataset dan pattern yang dibuat.
  6. Pertanyaan di luar konteks SAMSAT diarahkan ke fallback. Hal ini mencegah bot memberikan jawaban administrasi kendaraan untuk topik yang tidak sesuai.
  7. Pengujian otomatis menunjukkan 2 file test berhasil dijalankan dengan total 209 test case. Hasil tersebut menunjukkan bahwa fungsi dataset, pattern matching, fallback, multi-intent, dan format balasan Telegram berjalan sesuai skenario pengujian.

5.2 Keterbatasan Sistem

Sistem masih memiliki beberapa batasan. Pertama, chatbot tidak menggunakan AI generatif, sehingga jawaban hanya berasal dari dataset FAQ. Bot tidak membuat jawaban baru di luar data yang tersedia.

Kedua, kemampuan pencocokan sangat bergantung pada kualitas dataset, custom pattern, dan regex pendukung. Jika pengguna menulis pertanyaan dengan pola yang belum diwakili, bot bisa memberikan fallback.

Ketiga, perubahan dataset atau pattern masih dilakukan melalui repository. Setelah perubahan dilakukan, sistem perlu diuji dan dideploy ulang agar perubahan aktif pada bot.

Keempat, command /clear mengikuti batasan Telegram Bot API. Bot hanya dapat menghapus pesan yang message ID-nya dilacak dan diizinkan untuk dihapus oleh Telegram.

5.3 Saran

Beberapa saran untuk pengembangan berikutnya adalah sebagai berikut.

  1. Menambahkan dashboard admin untuk mengelola dataset FAQ, sehingga perubahan data tidak harus dilakukan langsung melalui file JSON.
  2. Menambahkan fitur import dataset dari CSV atau spreadsheet. Fitur ini akan membantu ketika data FAQ bertambah atau perlu diperbarui dari sumber eksternal.
  3. Mencatat pertanyaan yang masuk ke fallback. Data fallback dapat dipakai untuk mengetahui pola pertanyaan yang belum dikenali sistem.
  4. Menambahkan evaluasi kuantitatif seperti precision dan recall apabila data uji sudah diberi label jawaban yang benar.
  5. Mengembangkan rekomendasi beberapa jawaban ketika skor kandidat FAQ berdekatan, agar pengguna bisa memilih jawaban yang paling sesuai.
  6. Mengembangkan pendekatan hybrid dengan similarity matching, tetapi jawaban tetap dibatasi pada dataset yang sudah divalidasi.

Pengembangan tersebut dapat dilakukan tanpa mengubah tujuan utama sistem, yaitu menyediakan chatbot FAQ SAMSAT Bandung Timur berbasis pattern matching. Perubahan yang paling dekat untuk dilakukan adalah pencatatan fallback dan dashboard pengelolaan dataset, karena dua hal tersebut langsung membantu proses perawatan data setelah bot diuji oleh pengguna.
